# 知识库管理通则（权威单点真相源 · 域无关）

> 本文件是所有领域知识库（伦理场景库 / 工程经验库 / 产品 / 研究等）**共同遵守**的写入与管理规范。
> 各领域可在其下追加「领域规则」（例如伦理域的 `agents/ethics-chat/archive-rules.md`），
> 但**不得与本通则冲突**。通则管「怎么写才对」，领域规则管「这个域额外补什么」。

## 十条通则

### 1. 单一真相源
每条内容只写进**唯一位置**，绝不新建重复文件/文件夹；同一主题多次更新，合并进同一条。

### 2. 原子化
一条 / 一卡只装**一个**想法、一个事实、一个结论；塞了多个概念就拆开，互相链接。

### 3. 用自己的话重述
重述即加工；摘抄必附一句「我为什么摘这段」。纯抄录不沉淀。

### 4. 分层收纳
闪念（临时）/ 文献（概括）/ 永久（原子化）各有归属与生命周期；临时笔记 24 小时内转永久或丢弃。

### 5. 按用途分类（PARA）
放哪取决于「现在拿它干什么」，不是主题树；同一材料随用途在 Projects / Areas / Resources / Archives 间迁移。

### 6. 统一元数据
每条必带 `who`（来源 / scope）+ `when`（时间戳）+ `type`（语义 / 情节 / 程序）+ `status`（成功 / 失败）；多 agent 共享库用 scope 隔离归属，避免跨场景串味。

### 7. 证据锚定 + 可推翻
结论必须锚定可验证事实 / 来源；**新证据可推翻旧结论**——反思 / 经验不得固化错误判断。

### 8. 防污染
只留最终正确答案，禁「原来是错的 / 应改为」这类修正措辞；禁无关表格堆砌。

### 9. 监护原则（无错不删）
没有错误的内容**绝不删除**，默认「补充」，仅在确有错误时「修改」。

### 10. 遗忘机制
定期归档 + TTL / LFU 淘汰；超期未引用的降级 / 进待删清单——知识库必须能忘记。

## 领域规则如何挂接

- **伦理域**：见 `agents/ethics-chat/archive-rules.md`（在通则之上追加两档定性 🟡/🔴 + 程度分界 + 三小节结构）。
- **工程域**：追加「问题 → 根因 → 修复 + verification（如何验证这条经验仍适用）」，即知识沉淀官的入库 schema。
- 其它域：新开领域规则文件时，顶部加一行「继承自 `docs/knowledge-rules.md` 通则，本文件只补本域特化」。

## 与旧 archive-rules 的关系

原 `archive-rules.md` 的「唯一写入位置 / 防污染 / 监护原则」三条是**域无关的**，已上提为本通则第 1、8、9 条；
「固定结构 + 两档定性」是**伦理域特化**，留在 archive-rules，不再作为通用约束。
