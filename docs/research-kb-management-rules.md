# 知识库管理规则 · 全网调研与通用化升级

> 背景：现有 `agents/ethics-chat/archive-rules.md` 是**伦理场景库专用**的写入规范，不够通用。
> 本文从两条脉络（个人 PKM 方法论 + Agent 知识库工程实践）提炼一套**更通用、更先进**的管理通则，
> 作为 archive-rules 的升级蓝本。结论汇总，非原文照搬。

---

## 一、现状诊断：archive-rules 哪些通用、哪些特化

| 现有规则 | 通用性 | 说明 |
|---|---|---|
| 唯一写入位置（不新建文件/文件夹） | ✅ 通用 | 对应「单一真相源」，任何知识库都该有 |
| 固定结构（三小节缺一不可） | ⚠️ 特化 | 「结论/方案 + 性质与后果 + 灰/违界限」是伦理域结构，别的域要换骨架 |
| 定性只标两档（🟡/🔴） | ❌ 特化 | 灰/违二分只适用于合规域，通用域不该有 |
| 防污染（禁表格、禁修正措辞） | ✅ 通用 | 「只留最终答案、不写『原来是错的』」是普适的 |
| 监护原则（无错不删，只补充） | ✅ 通用 | 最有价值的一条，值得保留并推广 |

**结论**：archive-rules 的「唯一写入位置 + 防污染 + 监护原则」三条是通用的，应该提炼出来；
「固定结构 + 两档定性」是伦理域特化，应降级为「该域的领域规则」，挂到通用通则之下。

## 二、两条权威脉络

### 脉络 A：个人知识管理（PKM）方法论（人怎么写知识）

1. **Zettelkasten（卢曼卡片盒）**：原子化（一卡一想法）＋ 用自己的话重述（重述即加工）＋ 双向链接（连接涌现洞见）。
   三种笔记分层：`fleeting`（闪念临时）/ `literature`（文献概括）/ `permanent`（永久原子化）。
   **健康指标**（可量化，值得照抄）：
   - 月度新卡里链到旧卡的比例 > 60%；
   - 随机抽 10 张、愿意重读的 > 50%；
   - 每月至少一次「沿链接走到意外笔记」。
2. **PARA**：按「可行动性」而非「主题」分类——`Projects`（有截止的）/ `Areas`（长期维护）/ `Resources`（未来参考）/ `Archives`（封存）。同一份材料放哪取决于**用途**，不是内容主题。
3. **CODE（第二大脑）**：`Capture` 捕捉 → `Organize` 按用途整理 → `Distill` 提炼核心一句 → `Express` 表达产出。多数人只做了 C。
4. **渐进式总结**：四层提炼——原文 → 高亮 → 自己的话摘要 → 结合自身思考。
5. **量化经验法则**：2-5-10 原则（2 分钟读完 / 5 个链接 / 10 条笔记收尾）；24 小时规则（临时笔记 24h 内转永久）；20% 精华法（每次总结压到 20%）。

### 脉络 B：Agent 知识库工程实践（机器怎么写、怎么忘）

1. **统一记忆元数据格式**：每条必须带 `user_id`（隔离租户）/ `session_id`（溯源会话）/ `timestamp`（时间衰减）/ `memory_type`（语义/情节/程序）/ `status`（成功/失败）。
2. **写入与提炼规则**：事件驱动 + 周期提炼结合；用轻量小模型做后台提炼；压成**单条原子化陈述句**再写入。
3. **混合检索评分**：`得分 = α·语义相似度 + β·时间衰减 + γ·重要度权重`（不能只靠向量余弦）。
4. **记忆压缩与遗忘**：TTL + LFU 淘汰；超 N 月未引用自动降级/归档；记忆系统必须能「忘记」。
5. **版本化发布**：同一 source 文档每次发布生成新版本 ID，旧版标 `archived` 排除检索——根治「新旧版本互相矛盾、Agent 答出打架答案」。
6. **scope 字段**：多 agent 共享知识库时，每条带 scope 区分归属，避免 A 场景检索到 B 场景敏感数据。
7. **记忆分四层**：L1 工作记忆（context）/ L2 情节记忆（向量库）/ L3 语义记忆（图 + 向量）/ L4 程序记忆（工具/代码）。核心提醒：**记忆 ≠ 向量库**。
8. **原子化切块粒度**：记忆切块 64–128 token（单点事实），远小于文档 RAG 的 512–1024。
9. **重排截断阈值**：重排分 < 0.35 直接丢弃，不硬凑 Top-K（硬凑低相关 = 诱发幻觉）。

## 三、升级后的「知识库管理通则」（通用版）

> 目标：覆盖任何域（伦理/工程/产品/研究），archive-rules 退为「伦理域领域规则」。

### 通则（域无关，10 条）

1. **单一真相源**：每条内容只写进唯一位置，绝不新建重复文件；同主题多次更新合并进同一条。
2. **原子化**：一卡/一条 = 一个想法、一个事实、一个结论；塞了多个概念就拆卡，互相链接。
3. **用自己的话重述**：重述即加工；摘抄必附一句「我为什么摘这段」。
4. **分层收纳**：闪念（临时）/ 文献（概括）/ 永久（原子化）三层，或工作/情节/语义/程序四层，各有归属、各有生命周期。
5. **按用途分类**：PARA——放哪取决于「现在拿它干什么」，不是主题树。
6. **统一元数据**：who（user/agent/scope）+ when（timestamp）+ type（语义/情节/程序）+ status（成功/失败）——每条都带，检索才不串。
7. **证据锚定 + 可推翻**：结论必须锚定可验证事实/来源；新证据可推翻旧结论（反思不能固化错误）。
8. **防污染**：只留最终正确答案，禁「原来是错的/应改为」这类修正措辞；禁无关表格堆砌。
9. **监护原则**：没有错误的内容绝不删除，默认「补充」，仅在确有错误时「修改」。
10. **遗忘机制**：定期归档 + TTL/LFU 淘汰，过期未引用的降级/进待删清单——知识库必须能忘记。

### 领域规则（挂在通则之下，按域各写一份）

- 伦理域：在通则之上追加「两档定性（🟡/🔴）+ 程度分界 + 三小节结构」（即现有 archive-rules 的特化部分）。
- 工程域：追加「问题→根因→修复 + verification（如何验证仍适用）」。

## 四、落地建议

1. 把 archive-rules 的「唯一写入位置 / 防污染 / 监护原则」上提到通则，其余降为伦理域领域规则。
2. 通则落一份 `docs/knowledge-rules.md`（通用），archive-rules.md 顶部加一行「继承自 knowledge-rules.md 通则，本文件只补伦理域特化」。
3. 元数据格式（第 6 条）建议作为知识沉淀官入库的**强制 schema**——正好和它的 `verification` 字段衔接。
