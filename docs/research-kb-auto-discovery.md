# 知识沉淀官「自动发现 + 侦查」增强 · GitHub 调研

> 目标：让 `knowledge-settler-core.js` 的「自动发现」和「侦查」能力更强。
> 现状诊断：文件头声称「融合 Voyager / Reflexion / SKILL.md / MemGPT 四套范式」，但代码里**只落地了
> 被动 runOnce（喂什么沉淀什么）+ 启发式分类 + 关键词 suggestFor**；「自动课程 / 自验证 / 重要性打分 /
> 定期整合」这几样核心机制**只写在了注释里，没实现**。下面把缺口逐个映射到可借鉴的开源机制。

---

## 一、现状：缺的到底是什么

| 能力 | 现状 | 缺口 |
|---|---|---|
| 自动发现（自己找该沉淀什么） | 只能被动消费「已解决项」，等人喂 | 没有「自提议下一主题」的主动发现 |
| 侦查（主动探查根因/线索） | 无；runOnce 只做复盘，不主动探查 | 没有「巡逻式」的周期性整合 |
| 优先级排序 | 无；来什么算什么 | 没有「重要性打分」决定先沉淀/先查哪个 |
| 自验证 | 无；approve 靠人工 | 没有「入库前自验证是否仍成立」 |

---

## 二、可借鉴的开源机制（5 个，附仓库）

### 1. Voyager —— 自动课程（自己给自己布置作业）
- 仓库：https://github.com/MineDojo/Voyager （论文 arXiv:2305.16291）
- 机制：agent 从「当前状态 + 已有技能库」**自动提议下一个任务**，优先探索未知/新颖，最大化探索。
  技能库**自验证后才 commit**——生成的技能要跑过、确认能用，才进库；新任务先 `suggest_for` 检索复用，不行才生成。
- **借什么**：给知识沉淀官加一个「自动课程」——周期性扫描近期 trace + 现有库，**自提议「下一个值得沉淀/调查的主题」**（覆盖率缺口 = 新颖度），而不是等人投喂已解决项。这是「自动发现」的直接答案。

### 2. ADAS —— 元智能体 + 累积式 Archive
- 仓库：https://github.com/ShengranHu/ADAS （论文 arXiv:2408.08435，ICLR 2025）
- 机制：一个「元智能体」迭代地**编程/提议新的设计**，评估后入 Archive；Archive **累积式、不淘汰**，所有历史发现都可见、可被再次检索参考。
- **借什么**：知识沉淀官之上再加一层「元沉淀官」——定期盘点现有方法论库的**空白**（哪些问题反复出现却无对应经验），把它作为**侦查线索**投给沉淀官；库采用累积式，不淘汰旧条目（契合 archive-rules 的监护原则）。

### 3. Reflexion —— 证据锚定的反思 + 可推翻性
- 仓库/论文：arXiv:2303.11366
- 机制：失败后写一句自然语言反思，**必须引用具体失败步骤作证据**；反思进情景记忆，下一轮读出。
  关键警示（斯坦福 CS329Z 明确点出）：**反思一旦写进记忆，错误判断会在后续所有任务里固化复现**。
  因此需要两条保护——反思带证据、反思可被新证据推翻。
- **借什么**：沉淀官每条 insight 强制带**证据锚**（引用具体那一步/那次 trace），并支持「新证据推翻旧条目」（当前 `verification` 字段是起点，但要补「证据引用 + 可推翻」两条硬约束）。这是「侦查」可信度的根。

### 4. Generative Agents —— 重要性打分 + 阈值触发反思
- 论文：arXiv:2304.03442（记忆流 memory stream）
- 机制：每条记忆带三个派生分——`recency`（指数衰减）/ `importance`（LLM 自评 1–10）/ `relevance`（余弦相似）。
  检索综合三分；**importance 累计超过阈值（150）时触发一次反思**，把近期记忆归纳成高阶结论写回流。
- **借什么**：给沉淀官加「重要性打分」——每条 trace/事件用轻量 LLM 打 1–10 分，高分未解决项 = **侦查线索**；累计超阈值自动触发一轮反思。这解决了「先查哪个、先沉淀哪个」的**优先级排序**。

### 5. MemGPT / Letta —— sleep-time 后台整合 + 自编辑记忆 + git 版本化
- 仓库：https://github.com/letta-ai/letta （前身 MemGPT，arXiv:2310.08560）
- 机制：分层记忆（core / working / archival / recall）；「sleep-time」后台进程在空闲时**整理记忆**（压缩、归档、提炼）；
  agent 可**自编辑记忆**（运行时更新，人工可见可改）；支持 **git-backed 记忆版本化**（Context Repositories）。
- **借什么**：把沉淀官的 `runOnce` 从「事件触发」升级为「**sleep-time 定时巡逻**」——空闲时扫近期 session trace → 提炼 → 提案；记忆用 git 版本化（与工作台已有 `docs/agent-memory/{agent}.md` 随 git 走的约定一致）。这是「侦查 = 定期巡逻」的落点。

## 三、落地优先级建议

| 优先级 | 做什么 | 借鉴 | 一句话效果 |
|---|---|---|---|
| **P0** | 证据锚 + 可推翻 | Reflexion | 侦查可信度：每条 insight 必须引用证据，可被新证据推翻 |
| **P0** | 重要性打分 + 阈值触发 | Generative Agents | 侦查优先级：先查/先沉淀最要紧的 |
| **P1** | sleep-time 定时巡逻 | Letta | 自动发现：空闲时自扫 trace 自提议，不等投喂 |
| **P1** | 自验证后再 approve | Voyager | 入库质量：经验入库前跑一次「是否仍成立」校验 |
| **P2** | 元沉淀官 + 累积 Archive + 覆盖率缺口 | ADAS | 自动发现 2.0：盘点库空白，主动立项侦查 |

> 说明：P0 两条成本最低（不引入新依赖，复用现有轻量 LLM + 现有 state），价值最高，建议先做；
> P2 是「让沉淀官学会自己发现该学什么」的终极形态，可在 P0/P1 稳定后再上。
