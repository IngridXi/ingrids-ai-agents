# 伦理知识库 · 实答汇总规范（权威单点真相源）

> 本文件是「伦理场景库」中每条 `### 🤖 伦理 agent 实答` 块的**唯一权威结构规范**。
> 归档流水线（`run-scenes.js`）、前端手动提问同步（`index.html` 的 `ethicsSync` 链路）、
> 内容监护（`guard.js`）三者都必须遵守本规范；`docs/RULES.md` 引用本文件，不再重复维护。

## 一、写入位置与格式（铁律）

每条回答必须写进**对应场景的 `## 标题` 之下**，作为唯一的 `### 🤖 伦理 agent 实答` 块，格式：

```markdown
### 🤖 伦理 agent 实答 · YYYY-MM-DD HH:MM

**问**：<用户问题原文>

**答**：<结构化答案正文>
```

- **绝不**新建独立文件/文件夹存放回答；找不到对应场景才暂存「伦理对话·待归档」。
- 同一场景更新多次，**始终合并进这一个 `### 🤖 伦理 agent 实答` 块**，不堆积多个同名块。

## 二、答文结构（三小节，缺一不可）

```
### 结论/方案
（完整保留技术要点；每个做法末尾一行「分界：🟡… / 🔴…」点到即止）

### 性质与后果
（逐条细化「程度分界」，全篇最重要的一节）

### 灰/违界限
（核心判据 + 最典型分界阈值，2-4 句话）
```

## 三、定性铁律（灰 vs 违，两档）

1. **只标两档**：`🟡 灰色地带` / `🔴 明确违法`。**严禁**出现 `✅ 合规` 档、`✅` 符号、`合规档/合规线` 字样。
2. **每个做法必写「程度分界」**：落到可验证事实——有无真实交易 / 真实人员 / 真实资金流、有无伪造单证或合同、是否经审批、比例或金额阈值等。讲清「做到什么程度算灰、越过什么线变违法」。
3. **法条与定性以权威参考为准**（practices 分片 + 法务知识库原文），严禁自行编造法条条文号或刑罚；参考里没有的，写「可能触犯相关法律法规」，不瞎编具体条号。

## 四、输出纪律（防污染）

- **严禁 markdown 表格**（含 `|` 分隔符的行）；性质与后果一律用「灰色线（🟡）/ 违法线（🔴）」分条列表。
- **严禁**「原方案 / 原文 / 原先 / 原来 … 有误 / 应为 / 应改为 / 调整为 / 错标成 / 更正为」这类指向旧版本的修正性措辞——知识库只保留最终正确答案，读者不需要知道曾经有错误版本。
- 禁止模板化：每个做法的分界必须具体到该场景，不得每条写一样的空话。
- 禁止重复：同一做法的定性只写一遍，不在「结论/方案」与「性质与后果」重复罗列。

## 五、监护原则（内容守护，最高优先）

> **没有错误的已生成内容，绝不删除。默认动作是「补充」，只在确有错误时才「修改/润色」。**

1. 已有正确答案 = **保留**，只补充缺失的小节/要点。
2. 语义重复的新旧答案 = 保留**更完整**的一版，独特内容合并补齐，不无脑覆盖。
3. 确有问题（定性标错、法条背错、结构缺失）= 针对性修正该处，其余保留。
4. 润色仅限「使表述更准确清晰」，不改变事实与结论。
