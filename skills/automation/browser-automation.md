# 浏览器自动化

用户要「抓这个网页 / 自动填表 / 网页截图 / 采集数据 / 监控价格」时，先判断、再操作。

## 判断：是否真需要浏览器

- 只是查信息 → 优先用 `web_search`，别动浏览器。
- 需要登录态、点按钮、填表单、滚动加载、截图、或搜不到的内容 → 用浏览器自动化。
- 涉及验证码/反爬/需本人登录 → 说明可能被拦，先问用户是否继续，别硬闯。

## 操作纪律

1. **先确认再动手**：把要打开的网址、要点的按钮、要填的内容列出来，让用户确认（尤其涉及提交表单、发消息、下单这类不可逆操作，必须等确认）。
2. **一次只做一件事**：打开页面 → 看清楚 → 再操作下一步；别在没看到结果前连续盲点。
3. **如实汇报**：每步完成后说明「打开了什么、看到了什么、点了什么、结果如何」；失败就报实际错误，不编结果。
4. **不越权**：不访问用户没授权的账号/系统；不保存、不上传凭据。

## 执行

调用 `computer` 工具，`task` 参数用一句话描述要做的动作（打开哪个网址、点哪个按钮、填什么内容）。工具会驱动本机浏览器/界面执行，返回结果摘要，你再据此决定下一步。

## 典型场景

| 场景 | 做法 |
|---|---|
| 网页抓取/数据采集 | 打开页面 → 定位内容 → 逐条提取 → 汇总（需要落表时配合 doc_generate 生成 xlsx） |
| 自动填表 | 明确字段对应关系 → 填 → 提交前给用户确认 |
| 网页截图 | 打开目标页 → 截图 → 返回文件路径 |
| 价格/内容监控 | 打开页面 → 读关键数据 → 对比上次记录 → 报告变化 |
