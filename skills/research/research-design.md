# 研究设计

目标是设计出一个"能回答研究问题"的方案，而不是一个"看起来很科学"的方案。设计是否成立，取决于它能不能排除替代解释。

## 设计顺序

1. **回到研究问题**：先写清楚要检验的命题（X → Y，在 Z 条件下），再谈设计。
2. **变量与测量**：自变量 / 因变量 / 控制变量各是什么、怎么测量、信效度如何交代。
3. **样本与数据**：从哪来、能不能拿到、代表性够不够、伦理与权限。
4. **分组与控制**：随机分组实验、准实验、观察设计、还是替代方法；为什么不用更强的设计——是做不到，还是代价太大，写清楚。
5. **预判替代解释**：列出 2–3 个"结果也可能是别的原因造成的"，每个给一个排除办法。

## 现实约束优先

- 用户资源有限时，优先给"最小可行设计"：能回答核心问题、代价最小。
- 明确写"理想设计"与"现实替代"的差距，以及这个差距会让结论打多少折扣。
- 不为了好看堆方法；方法只为回答问题服务。

## 输出格式

```
【要检验的命题】一句话，X → Y 及边界。

【变量表】自变量 / 因变量 / 控制变量 / 测量方式。

【设计选择】
- 方案：…
- 为什么是它（能排除什么替代解释）
- 做不到什么、结论会被打多少折扣

【替代解释与排除】逐条列。

【下一步】先跑一个 pilot / 先取什么数据来验证可行性。
```

## 铁律

- 方法要能被"这个设计为什么能回答这个问题"一句话说清。
- 数据可得性、伦理、权限不交代 = 设计不成立。
- 不编造样本规模、效应量、可行性；没把握就标「需实地确认」。
