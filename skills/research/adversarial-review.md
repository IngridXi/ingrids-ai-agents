# 对抗式审稿（拒稿预演）

普通审稿给的是「平衡的弱点清单」——每个弱点平均用力，按 CRITICAL > MAJOR > MINOR 排开，但往往漏掉一个关键失败模式：**审稿人会写进拒稿信的那一句最致命的话**（那句话一旦被资深领域主席看到，论文就死了）。

本 skill 专门跑这一趟对抗：先让一个审稿人「必须下决心」写出最强拒稿理由，再让第二个审稿人逐条辩护，逼出真正承重的硬伤。

## 何时用

- 论文已过 1–2 轮常规审稿、分数稳定，但投稿前。
- 准备 rebuttal 时，预判 reviewer-2 的最强反对，提前准备回应。
- 标题过于高大、可能过度简化实际结论的理论性论文。

## 铁律

- 只依据给定文本判断，不臆造文献与数据。
- 攻击方必须「下决心」：其全部任务就是说服领域主席拒稿，不许写「总体不错但可进一步完善」这类空话。
- 辩护方逐条回应，把每条攻击归类为「已解决 / 部分解决 / 仍未解决」。

## 流程（双线程）

### 第一线程 · 攻击（写最强拒稿理由）

以审稿人身份，写一段 200 字以内的拒稿备忘录，聚焦单一最致命攻击，必须：

1. 只打一个点：标题主张 vs 实际证据的落差、假设 vs 结论的不匹配、范围过度声明、证据与结论的断层。
2. 落到具体段落 / 图表 / 数据（引用原句位置）。
3. 说明「为什么这一条足以拒稿」。

### 第二线程 · 辩护（逐条回应）

换一个「全新的」审稿人，逐条回应攻击，对每条给出：

- 判定：已解决 / 部分解决 / 仍未解决。
- 依据：文中哪一段、哪个证据支撑了辩护。
- 若「仍未解决」，说清缺什么才能补上。

## 输出格式

```
【最致命攻击】200 字以内的拒稿备忘录（单点，落到原文）

【逐点辩护】对攻击的每条拆解回应：
- 攻击点：...
- 辩护：...（引用原文位置）
- 判定：已解决 / 部分解决 / 仍未解决

【仍未解决的硬伤】列出真正承重、投稿前必须补的问题，按优先级排序。

【给作者的一句话】这条硬伤不改，最坏会怎样。
```
