# 视觉 QA（完成度检查）

目标：界面做完后，像质检员一样逐项挑问题，而不是"看着还行就交付"。

## 检查清单（逐项过）

1. **对齐**：文字基线、元素边线、图标与文字是否对齐；有没有 1–2px 的错位。
2. **间距**：是否都按 4/8 网格；同类间距是否一致；有没有忽大忽小。
3. **溢出**：长文本、长数字、长标题是否溢出/换行错乱；`overflow` 和 `text-overflow` 是否到位。
4. **对比度**：正文 ≥4.5:1、按钮文字 ≥4.5:1、大字 ≥3:1（详见「配色方案设计」skill 硬指标）。
5. **一致性**：同类的按钮、卡片、标签、图标样式是否统一；有没有"孤例"。
6. **空态**：列表为空、搜索无结果、首次进入时，是否有占位提示，而不是空白。
7. **加载态**：请求中是否有反馈；骨架屏/加载条是否统一。
8. **报错态**：出错时是否有可读的报错与重试入口。
9. **响应式**：几个关键断点（桌面/平板/窄屏）下是否塌了；小屏下元素是否拥挤。
10. **可点击性**：可点元素是否有 hover/active 反馈、命中区是否够大（≥40px 更友好）。

## 做法

- **截图对照**：把界面缩到 50% 眯眼看整体，再放大到 100% 看细节——很多问题在缩小后最明显。
- **一屏一个焦点自查**：满屏都是重点 = 没有重点。
- **逐条记问题**：给每条问题标位置 + 严重度（阻断/主要/次要），再统一修。

## 输出格式

```
【问题清单】按严重度排序：位置 + 问题 + 建议改法。

【阻断】必须修才能交付（溢出/错位/对比度不达标/功能态缺失）。
【主要】影响观感（间距不一致/孤例/层级不清）。
【次要】可优化（微调/留白）。

【复查结论】修完后是否达标。
```

## 铁律

- 只报"客观可见"的问题，不吹毛求疵到像素级主观偏好。
- 空态、加载态、报错态三个最容易漏，必查。
- 缩小看整体 + 放大看细节，两个尺度都过才算过。
