# 动效与交互手感

目标：动效是为了"让人理解发生了什么"，不是炫技。好的动效是察觉不到存在、但去掉就变糙。

## 时长与缓动

| 场景 | 时长 | 缓动 |
|---|---|---|
| hover 反馈 | 100–150ms | ease-out |
| 点击/按下 | 100ms | ease-out |
| 面板展开/收起 | 200–300ms | ease-in-out |
| 页面/大过渡 | 300–400ms | ease-in-out |
| 弹窗出现 | 150–200ms | 轻微 overshoot |

- **同一产品所有动效共用一套缓动**，不许这个弹窗 ease-out、那个 ease-in-out 乱跳。
- **超过 400ms 会显拖沓**，除非是刻意的大动画（如整屏切换）。

## 交互反馈（必须有）

1. **hover**：可点击元素悬停要有反馈（变色/抬升/描边），否则用户不知道能点。
2. **active**：按下瞬间要有"压下去"的反馈，别只有 hover 没 active。
3. **disabled**：不可用态要明确（降透明度 + 去光标），不能和正常态一样。
4. **状态变化**：数据加载/成功/失败/空，都要有对应视觉，不能"点了没反应"。

## 微交互清单

- 按钮点击：轻微缩放 + 颜色变深（100ms）。
- 卡片 hover：抬升 2–4px + 阴影加深，位移别超过 6px。
- 列表项 hover：背景微变，不位移。
- 开关/复选：过渡 150ms，别瞬变。

## 哪些地方禁止动

- **正文文字**：不加动画、不加闪烁。
- **高频交互区**：不用大位移动画，会烦。
- **数据加载**：骨架屏/进度条，别用花哨的旋转加载盖满。
- **无障碍**：尊重 `prefers-reduced-motion`，用户要求减少动效时全部退化为淡入淡出或直接无动画。

## 输出格式

```
【动效规范】时长表 + 缓动曲线（全站一套）。

【交互反馈】hover / active / disabled / 状态变化 逐项。

【微交互清单】按钮 / 卡片 / 列表 / 开关。

【禁动清单】正文 / 高频区 / 加载 / 无障碍。
```

## 铁律

- 全站一套时长与缓动，不许各模块各写各的。
- 每个可交互元素必须有 hover + active 两种反馈。
- 动效服务于"让人理解状态变化"，做减法；拿不准就少动或不动。
